  numid=696 1 (MM1<-LPI_TX_3)`, `arecord -Dhw:SE,0 -c1 -r48000` gives bit-exact

3.2 All 6 inputs zero: a1(ADC1)/a2(ADC2-INP2)/a3(ADC2-INP3)/d1(DMIC1)/d2(DMIC2)/
  d12 - via phonescan.sh acoustic sweep (speaker stimulus failed: bare-ALSA
  playback returns EINVAL, see 3.6; so sweeps were silent-room).
3.3 DAPM during capture is FULLY On: AMIC1->ADC1 (bias External1 on), DEC1 MUX,
  CIC1, I2S TX1, AIF1 Capture, LPI TX3 (AFE), PDM_TX, A_MCLK/TXA/TXD, MCLK, CDC_CONN.
3.4 AFE port 0x1035 (INT3/LPI_TX3) starts clean: chmode=SD0, MONO, ws_src=INTERNAL;
  sd-lines=<0 1> already in sirius DTS (dai@88); IBIT set_sysclk returns rc=0 (acked).
  NOTE: port->id is the FW port id (0x1035), not the DAI id (144).
3.5 Digital CDC register offsets match downstream sdm660_cdc exactly
  (0x10/0x18/0x28c/0x288/0x294...); analog MICB/ADC regs match too
  (0xF140/0xF160). TX_VOL_CFG=0x00 (unmuted), TX gain sane. PDM on, DEC1 clk on.
3.6 Bare-ALSA `aplay -Dhw:SE,1` fails EINVAL (even with PipeWire stopped), while
  PipeWire `pw-play` works (speaker OK). PipeWire shows a sink but NO sources
  (no UCM capture profile). Bare-ALSA capture runs but zero-fills.
3.7 LPI TLMM: enabling `&lpi_tlmm` (no pin states at all) hard-freezes sirius
  mid-boot (USB+display+net dead, same signature as 10-03 hang). The Oct-03 hang
  was likely the CONTROLLER, not the dmic pins. Driver `pinctrl-sdm670-lpass-lpi`
  does pm_clk from DT (node has no clocks) then touches 0x62b40000 -> bus/XPU hang
  suspected. Downstream uses a different driver (`qcom,lpi-pinctrl`) that presumably
  handles LPASS power. => DMIC via APPS pinctrl is BLOCKED until this is solved.
3.8 Stock (sirius V12.5.1.0 vendor, verified fingerprint) handset-mic=adc1 AND
  has full DMIC paths; bottom mic is claimed by both. Wiring (analog vs digital
  for the main mic) is UNRESOLVED - analog inputs look electrically silent
  (grounded/NC?), which points at digital mics, which are blocked by 3.7.
