# 面板显示修复记录 — 2026-09-15（sirius EA8074，1080x2244）

## 症状（两条，其实是一个病根）
1. 分辨率不对：DRM 上报 1080x2340，真屏是 1080x2244，纵向触摸越往下越偏。
2. 显示水平循环偏移：屏幕右边的一部分跑到左边去了。

## 根因
主线 `panel-samsung-ams639rq08` 驱动是从 pyxis（小米9 Lite，1080x2340 那块屏）抄来的，
三处 pyxis 残留跟 sirius 的 EA8074 对不上：

| 位置 | pyxis 旧值 | sirius 真值 | 影响 |
|---|---|---|---|
| drm_display_mode（驱动内） | 1080x2340，porch 64/20/64 | 1080x2244，h porch 48/16/48，v porch 28/12/28，60fps | 分辨率错误，连带触摸纵向偏移 |
| Page Address Set（0x2B） | 0x0000-0x0923（0-2339） | 0x0000-0x08C3（0-2243） | 垂直窗口多 96 行 |
| Set DDIC internal HFP（0x23/0x11） | 有（pyxis 调优值） | vendor 开屏命令里根本不写（用上电默认） | **水平循环偏移的元凶** |

vendor 真值来源（双重确认）：
- `android_kernel_xiaomi_sdm710-lineage-23.2/.../dsi-panel-ss-fhd-ea8074-cmd.dtsi` 的 timing@0
 （该文件唯一 timing）：width 1080 / height 2244 / hfp 48 / hbp 48 / hpulse 16 /
  vbp 28 / vfp 28 / vpulse 12 / framerate 60；on-command 里 `2B 00 00 08 C3`。
- bootloader cmdline：`dsi_ss_ea8074_fhd_cmd_display:config2`，对得上。
- 物理尺寸：65x135mm（驱动里原来 68/147 也是 pyxis 的，一并改）。

## 改动（提交 de49960 + 7c930f8，两次都在 feat/fts521-port）
1. `ams639rq08_mode`：clock 改为 (1080+48+16+48)*(2244+28+12+28)*60/1000；
   hsync_start/end/htotal、vsync_start/end/vtotal、width_mm/height_mm 全按上表改。
2. `ams639rq08_on()`：页地址 0x0923 改 0x08c3；删掉 Set DDIC internal HFP 两行
   （vendor 不写即默认，留着就是偏移）。
3. 没动的：vendor 的 B0/BB/CB/F7/D5/B1/EF 调参序列一个没抄（屏本来就亮，显示正常，不碰）；
   触屏侧 touchscreen-size-x/y=1080/2244 原来就是对的，不用动。

## 验证
- `/sys/class/drm/card0-DSI-1/modes` 报 1080x2244。
- 目测水平循环偏移消失；四角加对角线跟手（用户验证通过）。

## 教训
- 从别机型抄的 panel 驱动，mode/init 都要按本机 vendor dtsi 重对一遍，不能只改分辨率数字。
- panel 驱动是 builtin（=y），改完要重编 Image；且新 commit 会变 vermagic，
  modules 必须同一次编完重装（见主交接文档第 5 节铁律）。
